# Harness: как организована работа с AI

Идея: процесс воспроизводим. Любой человек или агент, открыв репозиторий, видит правила,
роли и проверки без пересказа из чата.

## 1. Источники правды (файлы, а не память)
| Файл | Что внутри | Кто читает |
|---|---|---|
| `CLAUDE.md` | правила проекта, стек, структура | все агенты |
| `docs/BRIEF.md` | задача и критерии приёмки | все агенты |
| `docs/DESIGN.md` | токены, экраны, состояния | builder, reviewer, keeper |
| `docs/design/` | эталонные скриншоты утверждённого дизайна | design-reviewer |
| `docs/QA-LOG.md` | журнал найденных и исправленных дефектов | qa-agent |

## 2. Роли агентов (`.claude/agents/`)
| Агент | Задача | Инструменты |
|---|---|---|
| `swiftui-builder` | Собирает экраны по DESIGN.md из токенов и компонентов | Read, Edit, Write, Bash |
| `design-reviewer` | Сравнивает скриншот с эталоном, выдаёт отчёт | Read, Glob, Grep (код не правит) |
| `qa-agent` | Тесты, линтер, логи CI, журнал дефектов | Read, Bash, Write |
| `design-system-keeper` | Ищет дубли компонентов и хардкод | Read, Glob, Grep (код не правит) |

Принципы: у каждой роли чёткие вход и выход; проверяющие агенты не правят код, исправляет только builder;
агенты не видят общий чат, поэтому всё нужное записано в их файлах и в `CLAUDE.md`.

## 3. Процесс
```
Задача → builder собирает → CI (macOS) собирает, тестирует, снимает скриншоты
      → design-reviewer и design-system-keeper смотрят отчёт
      → qa-agent читает логи, пишет тесты, ведёт QA-LOG
      → builder исправляет → повторяем до пустых отчётов
```

## 4. Автоматические проверки

Правило харнеса: всё, что можно проверить машиной, проверяет машина. Договорённости в `CLAUDE.md`
подкреплены хуками и тестами, которые срабатывают без участия модели.

### 4.1. Хуки Claude Code (`.claude/settings.json`, скрипты в `.claude/hooks/`)
| Хук | Когда | Что делает |
|---|---|---|
| `swift-tokens-lint.mjs` | PostToolUse `Edit\|Write` | Сразу после правки Swift-файла ищет хардкод цветов, шрифтов, отступов, радиусов. Правила читаются из `custom_rules` в `.swiftlint.yml`, источник один с CI. Нарушение возвращается агенту (exit 2), он исправляет в том же ходе. |
| `commit-gate.mjs` | PreToolUse `Bash\|PowerShell`, команда `git commit` | Блокирует коммит, если в изменённых Swift-файлах есть хардкод **или** Swift-файлы менялись после последнего запуска `design-system-keeper`. Правило 4 из `CLAUDE.md` теперь принудительное. |
| `keeper-stamp.mjs` | SubagentStop `design-system-keeper` | Пишет отметку времени и итог отчёта keeper в `.claude/state/keeper-last-run.json` (не в Git). |

Проверено вживую: правка с `.padding(12)` вне `DesignSystem/` возвращается агенту с указанием строки.

### 4.2. Тесты в CI
- **SwiftLint `--strict`** с кастомными правилами против хардкода.
- **Unit-тесты** логики: зоны давления (границы 129/84, 130/85, 139/89, 140/90), агрегация по периодам, валидация ввода, состояния загрузки.
- **Snapshot-тесты** (`HealthMonitorTests/SnapshotTests.swift`, swift-snapshot-testing): 10 кадров
  (главный: данные, loading, empty, error; давление: неделя, месяц, loading, empty, error, шторка). Сравнение по пикселям
  с эталонами в `HealthMonitorTests/__Snapshots__/` (precision 0.99, perceptual 0.98). Детерминизм: фиксированные
  часы, мок без задержки, фоновое движение формы выключено через `isAmbientMotionEnabled`.
  Нет эталона: тест записывает его и падает; CI выкладывает файлы артефактом `snapshots`, их смотрят и коммитят.
  При намеренном изменении дизайна эталон удаляют и перезаписывают тем же путём.
- **Аудит доступности** (`HealthMonitorUITests/AccessibilityAuditTests.swift`, `performAccessibilityAudit`, iOS 17):
  контраст, цели нажатия, подписи VoiceOver, Dynamic Type, обрезка текста, трейты на 6 экранах и состояниях (главный, давление, шторка, loading, empty, error).
  Любая проблема роняет тест, исключение только через список `waivers` с причиной. Отчёт по экрану: вложение `a11y-<экран>`.
- **UI-тесты** сценариев со скриншотами (`ScreenshotTests`, `FlowTests`).
- **Видео симулятора** всего прогона UI-тестов: артефакт `simulator-video`.

### 4.3. Где что смотреть после CI
| Артефакт | Содержимое | Кто читает |
|---|---|---|
| `xcodebuild-log`, `test-results` | лог и xcresult | qa-agent |
| `screenshots` | скриншоты экранов, отчёты аудита, diff snapshot-тестов | design-reviewer, qa-agent |
| `snapshots` | записанные эталоны | основная сессия (коммит после просмотра) |
| `simulator-video` | видео прогона | человек, design-reviewer |

## 5. Ограничения окружения
Разработка на Windows: Xcode недоступен, сборка и тесты выполняются только в CI.
Поэтому цикл проверки идёт через `gh run view --log-failed` и `gh run download`.

## 6. Как воспроизвести
1. Клонировать репозиторий.
2. Открыть в Claude Code, агенты загружаются из `.claude/agents/` при старте сессии.
3. Запустить задачу командой вида «используй swiftui-builder, реализуй главный экран по docs/DESIGN.md».
4. Проверить результат агентами `design-reviewer` и `qa-agent`.
